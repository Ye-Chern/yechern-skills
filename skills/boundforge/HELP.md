# BoundForge · 按需帮助

遇到对应情形时使用相应小节。普通研究从 README 或 skill 入口继续。

## 上下界矛盾：`INCONSISTENT_BOUNDS`

用 `state` 找到当前下界、上界及其论证，核对假设、方向和依赖。发现错误时 `retract --claim <id> --actor <研究者> --why <原因>`；保存修正材料后重新提交、核查。派生界会随撤回重算。

## 旧主张撤回后，后续成果消失

在 `state` 中查看 `dependency_blocked` 的主张及其 `depends`。若还能独立证明，保存独立论证并重新提交，使用实际仍成立的依赖。历史材料仍在账本里。

## 提示论证文件已改变或找不到

提交绑定的是当时文件的路径与内容指纹。恢复原版本后可继续核查；若确实修改了论证，将新版另存为文件并作为新主张提交，撤回有误的旧主张。

## 中断后仍显示工作正在进行

`state` 的 `open_works` 给出未关闭区间。用 `work-end --work <id> --actor <研究者> --outcome <实际情况>` 关闭，再继续研究；若已打开区间，也应先关闭它再开另一个。意外中断期间也会进入该区间的计时，记录中说明已知偏差即可。下次离开前结束 work。

## 已经 finalize，却想继续研究

已 finalize 的任务可继续读取、核查或撤回；新的研究活动使用一个新的数据库，并在开头引用旧任务的结果与材料。临时暂停时只结束 work，保持任务未 finalize。

## 模型表同步提示身份或版本不一致

查看任务初始化时绑定的 `model_index`、`model_id` 和 `model_version`，使用对应的表与版本。若要换模型，建立新的任务记录。预测只有明确裁定后才同步；具体命令见[账本说明](references/ledger.md#model-reliability-records)。

## 冻结尺度显示 `STALE`

查看被冻结尺度引用的界主张，处理已撤回或失效的论证。暂时按原始界和具体数学结果比较方向；需要新的固定尺度时，在新任务中明确设置。尺度参数说明见[决策模型](references/decision_model.md)。

## 想调整启发式或换研究角色

需要理解内外循环的估计与阈值时，读[决策模型](references/decision_model.md)。当前方法卡住、希望换个角度时，读[角色与方法](references/roles.md)，并可用 `role` 在当前 episode 内切换。

`COLLECT_BASELINE` 表示当前片段的时间记录较少，是建议而非继续等待的要求；已有证明、障碍或明确新方向时直接按研究结果行动。具体五分钟初始建议与记录粒度的影响见决策模型。

## 从别处运行时找不到 boundforge 模块

先进入已安装的本 skill 目录，再运行 `python -m boundforge --db <任务数据库绝对路径> ...`。数据库与论证文件留在任务目录；这里仅作为程序入口。也可把本 skill 目录加入当前进程的 `PYTHONPATH`。

## 搬迁工作目录或分享研究记录

当前版本按提交时的绝对路径绑定论证文件，模型表同步键也包含数据库路径，尚无整体迁移命令。仅复制数据库无法自动重绑附件。恢复原路径，或在新任务中以新路径重新提交并核查材料；不要直接改写带哈希的旧事件。若分享运行记录，另做脱敏副本，检查论证内容、actor、文件路径和模型表中的本地路径；公共代码包不包含个人账本。
