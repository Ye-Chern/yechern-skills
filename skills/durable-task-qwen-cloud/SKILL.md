# Qwen 云端长任务

在 Qoder Cloud 中继续用户指定的工作。优先复用项目原有入口或一份短状态文件，使下一轮知道目标、进展、关键取舍和下一步。记录方式与频率按恢复风险选择；短任务不需要套用整套账本或计时流程。

## 开始或恢复

1. 解压技能包或恢复包到实际工作目录，确认用户的目标、最新约束、验收方式和授权。首次运行时，按需检查当前目录、工具、Python 与交付方式；未确认的能力标为未知。
2. 若有恢复包，先检查实际解压副本及其文件布局，再读取当前入口和相关证据。遇到账本时，先用 [references/ledger.md](references/ledger.md) 的接口执行 `python3 <skill>/scripts/task_memory.py resume --root <copied-ledger>`，读契约和新生成的恢复入口，再按 ID 查看当前证据。旧摘要、旧路径或旧进程记录不能补全缺失材料。
3. 只有短记难以追踪关键依据、撤回影响或多层依赖时才启用账本。通常无需逐轮通读脚本；按引用使用接口，遇到错误再读实现。首次云端工具与路径核查见 [references/cloud-runtime.md](references/cloud-runtime.md)。

## 推进工作

从当前前沿选择能解除阻断、验证关键前提或完成核心产物的动作。研究任务按需读 [references/research.md](references/research.md)，区分严格推导、有限计算与探索线索。长计算按工具限制拆成可恢复单元，保存输入范围、生成器版本、原始结果、独立校验和提交位置，再更新入口。

记录中分清证据、结论、选择和待办。关键结果应能回到来源、版本、验证方式与适用范围。账本中的 `accepted` 只表示在该节点范围内验收；文件或前提变化后复核受影响的结论。细小试做可合并记录，然后继续推进。

有用户指定的总时长时，才用 `scripts/work_budget.py` 记录该窗口，不得在恢复时重置旧截止时间。仅当任务需要跨轮自动续接且当前会话支持真实完成回执时，才使用有限计时监视者；间隔按任务和剩余窗口选择，回执到达后核对实际结果再决定是否继续。计时脚本本身不会唤醒模型。详细边界见 [references/wake-events.md](references/wake-events.md)。

## 交付与续接

结束本轮前更新恢复入口，写清已完成和未验证范围、当前阻断、下一动作与验收方式。超时、断线或无回执后先核实动作是否已产生结果；结果未知时先查证，只有确认未执行或可安全重复时才重试。

需要跨轮或跨环境继续时，暂停项目写入并生成恢复 ZIP。账本项目使用 `scripts/cloud_bundle.py pack` 并运行 `verify`；轻量项目按需打包恢复入口、必要说明和任务文件。生成 ZIP 不代表已经上传，须用当前环境实际提供的附件交付方式确认用户可取回；工具不可用时说明文件所在位置和阻断。详细迁移与异常处理见 [HELP.md](HELP.md)。

通用能力边界、证据范围和授权原则见 [NOTICE.md](NOTICE.md)。
