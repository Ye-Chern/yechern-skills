# Qwen 云端长任务

用于 Qoder 移动端 Cloud 任务。控制管理调用，每个阶段结束留下下一轮可执行的入口。技能包与任务恢复包分开上传。本技能不能提高平台时间上限、扩大授权或保证后台存活。

## 上传后开始

1. 解压到新的工作目录，读取本文件。不要假定已自动安装技能。先识别用户给的任务和已有恢复入口，保留原目标与最新约束；遇到多个项目或账本，按入口指定选择，不凭文件名自动挑库。
2. 从已有材料确认目标、验收、授权、重要输入/偏好和未决条件；只补影响下一步的缺项，可与当前状态写在同一文件。首次云端运行按 [cloud-runtime.md](references/cloud-runtime.md) 做便宜的工具/路径/交付能力检查；没测过的能力写 unknown。辅助脚本通常按相关引用的命令接口直接使用，需要排错才读实现；不要逐轮通读全部源码。
3. **已有恢复包先核对实际解压副本。** 有账本时先读 [ledger.md](references/ledger.md) 的命令接口，按示例执行；通常无需每次通读辅助脚本源码，需要排错时再查实现。本版账本放在项目内部，根目录从账本相对位置解析，整个项目保持布局复制即可。旧 durable-task 账本必须先显式 `relocate --project 新项目根`；失败不刷新哈希。随后 `resume` → CONTRACT.md → 新 CAPSULE.md → 按 ID `show` 当前证据。绝不用旧摘要补出缺失事实。
4. 默认复用已有入口或一份短状态文件，保存目标、当前进展、重要取舍/回退原因和下一步。模型按任务、工具和恢复风险选择步骤、布局与记录频率；视觉、写作、交互任务可以反复看效果、判断和修改，按需保留版本与反馈。只有简记难以追踪关键依据、撤回影响或多层依赖时，才增加结构或使用 [ledger.md](references/ledger.md) 和 `scripts/task_memory.py`。时长、文件数和压缩本身不要求建账本；结构过重时可以收简，保留仍有效的来源与失效信息。

## 一个工作窗口

- 用户给时长时用 `scripts/work_budget.py start` 记录本窗口截止时刻和交付预留；未给时长不擅自填几小时。恢复同一窗口不重置截止时刻；用户明确续时则记录新指令与新窗口，保留旧预算，不能只换文件名延时。阶段边界查看剩余时间，大约每 20 分钟检查一次是否仍在解除核心问题。为用户要求的长窗口，若本会话实际支持后台子代理完成回执，按 [wake-events.md](references/wake-events.md) 设一个有界计时监视者，使主回复结束后仍有机会继续；主代理照常推进任务，不睡眠凑时长。目标提前达到就交付。
- 从前沿选择一个可验收动作：验证最薄弱前提、解除共享阻断、完成核心产物。保存有助后续工作的估计、结构或中间证书，不把失败办法升级成“所有办法都不可能”。数学任务按 [research.md](references/research.md) 分清证明、有限穷举与数值线索。
- 长计算先用小样本估时，切成能在本次工具限制内完成的单元。每个单元保存输入范围、生成器版本、原始输出/证书、独立校验和完成标记，再原子提交。恢复以已提交且可验的单元为准，不能仅凭日志中的 OK。具体格式见 cloud-runtime。
- 在记录中分清结论、证据、选择和待办；账本模式下用稳定 ID 连接重要依赖。关键结果、撤回、用户新条件或阶段产物会影响恢复时，及时更新原入口和受影响的当前报告。细小试做可合并记录，接着推进问题。
- 绑定稳定结果和对应生成器。滚动进度、CAPSULE、活账本和正在增长的导出不是固定证据。依据变化或撤回时，复核受影响的重要结论；账本模式按 `audit` 给出的上游优先列表处理，不批量换哈希或版本号让旧结论自动复活。
- 进程、PID、ETA 和计时器记录都只是观察。普通脱离工具的后台 Python 本身不发送模型消息；宿主跟踪的后台工具/子代理完成事件可以触发继续，须使用实际可用接口并核对回执。只保留一个计时监视者，沿用本窗口绝对截止；任务提前完成、交付预留到达或触发失败时停止续设。没有可用回执机制时保存恢复包，由用户下一消息继续。事件机制不保证环境数小时保活。

## 交付与恢复

预留时间到或准备结束本轮时，停止发起新长搜索，先完成已能闭合的验证。状态按需写已验收范围、未决问题、撤回/禁用项、下一动作和验收方法；有分单元作业时记录最后已提交单元。完整性审计不等于数学或程序正确。

新结论闭合了原待办时，更新当前状态再写报告。账本模式下，交付前对照最新关键节点，核对报告结论、仍未解决的问题、下一动作是否一致；发现已完成证明仍在 CAPSULE 的 next_action/open_questions 中，先更新 focus 再生成恢复包。`resume` 只能再生已记录的前沿，不能自动替你判断旧待办已解决。

完成、用户停止或预算进入交付时，取消本任务的计时记录并停止本任务监视者（若工具支持）。迟到、重复或空回执只核对已记录任务 ID/结果；不能因此新开窗口、重启监视者或复活已完成任务。

暂停项目写入后，用 `scripts/cloud_bundle.py pack` 为账本项目生成恢复 ZIP；工具在副本中重建恢复视图、导出和核对字节，保留原工作树。未完成且仍需复核时仅显式用 `--allow-review`，报告这些 ID。轻量模式用标准 ZIP 打包恢复入口、必要的任务说明与所需文件，注明未使用账本工具验证。

**生成 ZIP 不等于交付。** 用本环境实际提供的附件/Artifact 工具上传产物和恢复 ZIP，确认用户可下载；工具不可用时明确说明仍仅在沙箱内，给出阻断和可用替代。禁止编造下载链接、工具名或“已上传”。只有已导出的文件可作为下一轮输入；沙箱 checkpoint 只降低仍能取回它时的续跑成本。

交付说明简短写明做成了什么、实际怎样验证、还有什么未完成以及下一轮上传哪些文件。保留恢复入口与失效历史，不宣称达到通用长程成功率。实践中发现问题先在任务记录可复现场景；不要自行修改原技能、全局配置或收费服务。计时监视者只按上述有限协议使用；其他 agent 按用户任务授权决定。
