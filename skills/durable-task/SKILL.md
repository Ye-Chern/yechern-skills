# Durable Task — 长任务结构与恢复

保存足以继续工作的状态。成功标准是恢复后能作出正确的下一步；记录的形式和粒度由任务需要决定。

## 自主选择记录方式

模型根据任务、可用工具和恢复风险选择工作方法、步骤、文件布局与记录频率。默认复用已有入口；一份 `work/state.md` 就可以。把目标、当前进展、关键取舍或回退原因、下一步及验证方式写在一起，已有材料用链接引用，字段按需保留。

视觉、写作和交互任务可以按“看效果、判断、修改、再看”的循环推进，允许主观品味和探索。保留有助于恢复的版本、反馈和重要取舍即可，不必记录每次尝试或给每个子问题建依赖。

当简记已难以追踪关键依据、撤回影响或多层依赖时，再增加结构或使用账本。任务长、文件多、经历压缩本身都不要求升级。记录过重时可以收简，保留仍影响后续判断的来源、失效信息和恢复入口。需要选择领域验证方法时读 [profiles.md](references/profiles.md)。

## 开始或恢复

1. 识别并复用项目的 README、状态、计划或日志。保留原目标，合并用户的新约束，确认当前版本。
2. 从已有材料确认目标、品味、验收条件、授权、关键输入和不确定性；只补影响下一步的缺项，可写在同一状态文件中。缺少决定性输入时早问；能独立推进的部分继续。主观目标按偏好处理。
3. 选择适合产物的验证方式和专业 skill。按实际需要保存状态；新建路径可用 `work/state.md`。需要版本化账本时才读 [protocol.md](references/protocol.md)，使用 `scripts/task_memory.py`；脚本只用 Python 标准库。
4. 本技能脚本模式恢复：先 `resume` 重建短入口，再读契约并按 ID 取回相关证据。需核查完成记录时用 `audit --strict`。其他工具账本先核对格式；不兼容时按原协议或手工恢复。旧 capsule 不当现况。
5. 接收恢复包、换环境、准备中断或管理长进程时，按需读 [handoff.md](references/handoff.md)。核对入口所指材料和产物的用途、版本与完整性；旧路径、PID、窗口预算和“完成”标签不能替代当前检查。

## 推进一段有意义的工作

- 从当前前沿选一个动作：解除共享阻断、验证最脆弱的前提、或完成可验收的产物。优先选择能区分候选解释的实验，避免把“多收集一点材料”当默认进展。计划保留少量下一步，可以重写；被否定的理由留在历史里。
- 按完成标准检索数据；保留关键输入、工具原始结果或最小可复现材料，给来源版本、符号/章节/锚点和适用范围。只保存影响后续决策的内容，不保存隐藏推理逐字稿，也不复制全部聊天。
- 大结果留在可取回的文件中，先读索引、覆盖范围与当前相关部分。摘要或投影注明省略范围，取不到全文时不冒充完整；滚动进度与已验收的冻结证据分开。
- 在记录中分清证据、结论、决定和待办；使用账本时以稳定 ID 连接关键依赖。`accepted` 是在记录的 scope 内验收，绝不是全局真理。重要结论先读证据，再用适合领域的验证；命令退出成功不等于语义正确。外部或自己的“已完成”声明都需要具体依据，但不要无理由重复已经足够且仍有效的检查。
- 文件变化、证据撤回或上游修订使下游进入复核状态。不能因路径相同或新检查通过就自动沿用旧结论。手工记录也要识别并复核受影响的重要结论，无需为此建立完整依赖图。
- 关键决定、反例、撤回、用户约束变化或阶段产物会影响恢复时，及时更新原入口和受影响的当前报告；预计中断前也保存当前状态。不能依赖能够预测何时发生压缩。试做与细小调整可合并记录，避免记忆管理挤占实际工作。
- 阶段结束时检查工作是否更接近用户目标，再决定继续、换路或交付。新的连接可先作为候选保留，经相应验证后用于结论。

## 恢复与完成的硬边界

恢复后须能回答：现在要交付什么、哪些事实可用、哪些被撤回、凭什么、下一步如何验收。答不出来就定向读取相关记录，不能靠摘要补全缺失事实。

脚本的哈希只检验字节漂移，依赖图只检查已声明的边；它们不检验结论的正确性、未知依赖或授权。数据库事务保护账本写入，不保护外部产物或磁盘备份。需要时保存独立交付快照并比对；不擅自恢复覆盖用户文件。

交付时按约定的目标与验收方式验证产物，报告已完成与尚未验证的范围，并留下可继续工作的入口。文件只有“存在”不够。skill 不创建 goal、自动化、子代理或外部消息；这些仍按用户授权及当前系统规则执行。长任务不意味着被动等待或无限循环。

中断后先核实已落盘或已发生的结果，再决定重做哪一步；未知结果不等于失败或从未执行。交付收尾核对本任务仍需的进程与未完成项，不把整段工作盲目重跑。

## 持续改进接口

遇到真实恢复失败、重复劳动、误信旧证据或管理成本过高时，读 [evolution.md](references/evolution.md)，在本技能的 `state/IMPROVEMENTS.md` 追加可复现观察。依用户对本技能的既有授权，可实施窄范围、可回退的改进；没有授权时记录提案。

先确定失效机制，再做最小修改和相应重放。区分建议、已实施、已验证、已回退。保留修改前的相关文件和回退方式，不把单次成功写成普遍效果；不要积累万能规则或改变其他 skill、全局配置与授权边界。

设计取舍见 [research.md](references/research.md)，仅在需要时读取。操作和改进日志各自按需读取，避免每次加载全部参考材料。
