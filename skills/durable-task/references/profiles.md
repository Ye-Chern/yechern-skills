# 按任务选择记录与验证

遇到不确定的验收或恢复问题时，可用以下问题辅助判断；不要求填写表单：什么产物算完成，什么材料支撑结论，如何验证，什么变化会使结论失效，用户的偏好是什么。只补当前任务需要的答案。

## 工作方法

- 使用当前可用文件工具和项目已有布局；新中间材料可放 `work/`，交付可放 `outputs/`。Windows 用 LiteralPath 或参数数组。
- 文档、表格、数学研究、网站等任务继续采用相应专业 skill 的验证方法。
- 研究：实际读取来源，分清摘录、推论和猜测；新鲜或不确定事实先检索。记录重要来源的版本和定位。检索失败只说明本次覆盖面。
- 代码：验证当前修订的实际行为和覆盖范围，只跑相关必要检查。
- 视觉与交互：可以用效果预览、截图比较和用户反馈反复调整。阶段性保存选定版本、重要反馈、回退原因及下一次要看的效果；不要求给审美判断编分数或逐步证明。尚未看过的效果标为未验证。
- 创作与文学解读：允许主观验收、自由联想与鲜明读法，依据是参考和确认的偏好。笔记按需区分原文与自由延展；事实核查仍按来源判断。
- 调查：分清观察、因果解释和处理选择；优先做能区分候选解释的检查。

## 记录可以随任务调整

默认使用已有入口或一个状态文件，足以找回目标、当前版本、关键取舍和下一步即可。多个文件或长时间工作也可以保持这种方式。

当简记难以可靠追踪重要证据的版本、撤回影响或相互依赖的结论时，可以增加索引、分拆文件，或使用账本。账本只记录影响后续判断的节点。选择账本后遵循其版本与恢复协议。

可以在工作中增加或减少结构，保留仍有用的依据与失效记录。不需要按模型强弱预设固定模板；用实际恢复是否可靠、记录成本是否合理来调整。

接管已有项目时复用原入口。只读任务如需留记录，写在自己的工作目录；不移动原文件。旧摘要与状态表不能算作本次已测。
