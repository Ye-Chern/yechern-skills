# 任务专门化接口

先按任务定义五项，不需要生成新 skill 或新 agent：
1. **Object**：什么对象构成一次可验收的工作？代码模块、研究命题、来源条目、文档段落或决策方案。
2. **Evidence**：什么材料支撑结论？原始结果、源码、用户参考答案、原文、测量；哪些只是线索？
3. **Validator**：如何区分正确、错误、未知？写下具体方法、预期结果和覆盖边界。
4. **Invalidation**：什么变化要求复核？文件字节、数据版本、领域假设、用户目标、环境。
5. **Taste**：怎样判断符合用户想法？用户给的好/坏样例、禁止项、权衡；推测标为待定，允许用户更正。

## Codex 默认接口

- 用当前文件工具读写；默认 work/ 中间材料、outputs/ 交付。Windows 用 LiteralPath 或参数数组；不用把路径串接成跨 shell 命令。
- 本技能处理长期工作状态。文档、表格、数学研究、网站等任务继续使用相应专业 skill，不复制它们的验证手册。
- 研究：来源实际读取，摘录与推论分开；新鲜或不确定事实先检索。记录版本与章节，不把 arXiv HTML 中可能的构建日期当投稿日期。检索失败写覆盖面，不能推出不存在。
- 代码：验收绑定当前文件/修订及实际覆盖范围。语义正确性由行为检查和必要的独立方法判断，只跑相关必要检查。
- 创作与文学解读：允许主观验收、自由联想与鲜明读法，依据是参考和确认的偏好；不逐项要求解读证明，也不为数字化发明分数。保存笔记时轻量分清原文情节与自由延展；资料核查仍按来源实际范围判断。
- 调查：区分观察、因果解释、处理选择。同一现象可能有多个原因；优先做能区分它们的检查。一次命令失败只证明此次尝试失败。

## 模式选择

**轻量**：文件少、依赖简单，使用既有 README + 当前状态 + 追加决定日志。仍给来源、撤回和下一步，不为使用技能引入数据库。

**账本**：多分支、长链依赖、反复撤回、文件回写或跨会话恢复。用稳定 ID、依赖版本、文件绑定和恢复入口。关键前提和重要阶段才入账。

**接管已有项目**：既有入口作为根，状态和日志作为来源。只读请求就在自己的 work/ 建账本，不移动原文件。旧摘要与状态表不能重新包装成“本次已测”。
