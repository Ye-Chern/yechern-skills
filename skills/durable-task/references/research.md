# 设计依据与范围

工作上下文保存当前前沿；外部文件保存来源、版本和失效条件。恢复入口只路由当前相关材料，结论仍需回到证据检查。

## 结构

- 契约记录目标、验收条件、授权和偏好。
- evidence、claim、decision、task 分开记录，用稳定 ID 连接必要依赖。
- SHA-256 绑定文件字节，依赖版本阻止旧结论自动恢复有效。
- SQLite 事件保存变更历史；CAPSULE 是可重建视图。
- 重要变化时保存状态，避免每轮复制整段聊天。

轻量任务使用已有入口和日志。多分支、反复撤回或文件漂移重要时再使用账本。

## 工程参考

[SQLite 的事务说明](https://www.sqlite.org/atomiccommit.html) 用于理解数据库提交边界。本实现使用标准事务和默认 rollback journal；外部文件与数据库之间没有跨文件事务。

设计也参考了 [dsh-ops 固定修订](https://github.com/T-Auto/dsh-ops/tree/c4d829a012d8e9959f36150794edc354e49452ee) 的结果核验、外置结果和进程状态区分。此处未包含其源码或执行器，也不继承它的运行保证。

## 验证范围

脚本测试检查文件漂移、依赖失效、版本冲突、迁移和视图恢复。它们不判断结论语义、未声明依赖或模型是否遵守指令。实际恢复收益、读取成本和管理开销需要针对任务评估。
