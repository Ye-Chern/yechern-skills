# PALIMPSEST — 数学研究与证明

主 agent 负责理解目标、推进研究、核查关键推论并整合结果。子代理可以帮助探索，但结论仍由主 agent 按证据判断。

## 普通研究路径

1. **先固定要回答的问题。** 保留原题的对象、定义、量词、假设和结论。检查会影响证明的歧义或边界情形；不要为了流程完整而机械枚举。
2. **找到当前障碍。** 根据题目决定先做什么：构造、证明、找反例、查文献或计算。优先选择能尽快区分路线的一步。研究性命题或关键依赖需查到可用的原始定理，并核对其假设；搜索摘要只能提供线索。
3. **按需分工。** 主 agent 可以独立完成简单问题。只有当另一项工作有清楚边界、能产出可核查结果时才委派，例如独立反例、不同证法、关键引理或来源核对。特殊调度见 [orchestration.md](references/orchestration.md)。
4. **保留问题的变化。** 发现反例时，说明它否证的是原命题、某个引理还是一种方法。可以继续研究修订版，但并列写出原题与新题、触发修订的证据，以及二者是否等价、蕴含、加强、削弱或不可比；关系未证时标明未知。方法失败不等于命题为假，没找到反例也不证明条件等价。修订版成立不会使原题自动成立。
5. **按实际证据报告。** 计算说明它覆盖的对象、范围和假设。自然语言证明要闭合关键推理并核对文献条件。形式证明要对应原题完整目标和实际依赖。分别标记实验支持、文本证明、机器检查或反例；工具报错、有限样本通过和搜索未命中各自只说明其实际范围。
6. **交付可理解的结果。** 说明核心想法、困难步骤、用到的假设、剩余缺口，以及结果是否满足原目标。研究仍未完成时，给出目前最有价值的部分结果和一个有依据的下一步。

结果状态可按具体命题使用：`open`、`candidate`、`experiment-supported`、`proved-informally`、`proved-formally`、`disproved`、`needs-review`。状态绑定到明确陈述及其假设；条件结果要单列尚未推出的条件。详细边界见 [verification.md](references/verification.md)。

跨阶段研究或证据撤回时，使用 [memory.md](references/memory.md) 保留现行结论、来源与受影响的依赖。遇到特殊形式化、计算审计或恢复问题时再查 [HELP.md](HELP.md)。

通用能力边界见 [NOTICE.md](NOTICE.md)。本技能的研究设计依据与维护行为样例分别见 [research.md](references/research.md) 和 [evaluation.md](references/evaluation.md)；普通解题无需阅读。
