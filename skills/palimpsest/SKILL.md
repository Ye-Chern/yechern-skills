# PALIMPSEST — 可核查、可恢复的数学研究

主 agent 是有数学责任的研究负责人：可以证明、否证、改写、整合，也必须核查关键推论。子代理提供隔离的研究工作，不是投票者；角色名、数量、模型强弱均不能保证独立或正确。

保留 Lakatos 的精神：失败可以产生更好的引理、概念和问题，但必须保留原问题与修订之间的差别。目标是**可信结果、可解释的核心思想、可复用的数学结构，以及清楚的未知边界**。正确性、目标忠实性、研究价值分别判断。

## 1. 建立任务契约

先查已有任务入口；接续任务时复用它。记录：

- **原问题**：逐字保留题面；明确对象、定义、量词、参数范围、边界和允许调用的理论。给原问题稳定 ID `P0@1`。
- **研究目的**：解题、证明指定命题、最小假设、寻找反例、发展理论或形式化。未指定时先解决原问题；有用的推广可以作为旁支。
- **验收与交付**：默认给完整可读的数学结果、证明状态和必要的过程记录。纯自然语言证明可以作为完成结果，须通过逐项审查并如实标明尚未形式化；用户要求机器认证时按该要求验收。
- **资源与环境**：遵守用户给的限制；只使用当前实际可用工具、并发槽和文件权限。难度 1–5 可作探索提示，不决定固定代理数，不因自报高难度停工。未给预算不擅自创建 goal 或自动化，也不承诺无限搜索。

用户指定目录时使用该目录；否则复用项目布局，或在当前工作区为任务选择隔离目录，避免并发写入冲突。中间材料进任务 `work/`，最终文件进任务交付目录。修改本技能本身时不新建数学任务。

长任务从一开始用 [memory.md](references/memory.md)，已有 durable-task 时结合其验证和恢复协议；轻量任务只需简短契约、结果和关键记录。

## 2. 校准对象，先寻找便宜的分歧

展开歧义和隐含存在性；检查空对象、最小维数、退化参数、标准例、极限和量词次序。优先检测会同时影响多条路线的前提，不为每个题机械枚举 n=0/1/2。

研究性命题或依赖外部结果时检索原始文献。搜索同义表述、等价对象、定理名称、反例和相邻领域；读到定义与完整定理后，逐项匹配假设。Math Stack Exchange 可以提供线索，不能代替被引用的原定理。mathse-lookup 可用则按需使用，检索不限定为该渠道。来源记录见 [verification.md](references/verification.md)。

写下当前最实质的障碍和几条可区分的路线。可以换表征、归纳量、对偶、构造或使用已知结构定理；**换域、换量词、增添前提、削弱结论是在改问题，不自动算同一问题的证明路线**。以可检查的起步和关键引理判断可行性，不将四个自评布尔值变成能力测量。

发现合法反例时，原命题状态为 `disproved`。若研究范围允许继续，探索修订版；原问题不会因修订版成立而变成已证明。必要的澄清和旁支继续推进，不把常规路线选择交回用户。

## 3. 按当前障碍调度，而非固定五拍

需要多代理时先读 [orchestration.md](references/orchestration.md)。调用当前环境的原生子代理工具；工具不可用时串行工作并说明核查独立性的限制。不要启动旧模型服务或用脚本模拟子代理。

简单命题可由主 agent 完成。复杂任务通常先安排少量实质不同的工作：一条主证明路线、一个针对共同薄弱点的反例任务，或一个能解除共享阻断的引理/文献任务；存在真正不同的第二路线时再加。保留主 agent 整合和计算的时间，队列服从实际槽位，允许逐步返回和早期否决。

每个任务指明：命题 ID/版本、精确目标、允许前提、输入出处、所检验的区别、交付与停止条件、绝对工作目录和文件所有权。代理只能写自己的分支目录，不共同改主证明或账本。返回完整的可审查结果与必要证据；不索取私有思维链、全 transcript 或只有结论的赞同。

循环的单位是一个**可检验的障碍**：

1. 选择下一项能区分路线或解除依赖的动作；生成证明、局部反例、模型、文献匹配或形式化。
2. 校验输入版本和结果范围；提取精确的证明义务，不把代码退出成功当数学成功。
3. 在有完整候选后安排独立审查。审查者先只看题面/定义、候选和必要来源，看不到作者身份、其他评分和预设通过结论；先独立重建关键步，再针对具体分歧交流。隔离上下文降低相互影响，不使同模型错误独立。
4. 将错误、修正、部分结果和新问题登记。重新派活必须带具体错误位置、未闭合义务、新证据或不同推理/表征任务；纯“再检查一遍”不构成进展。具体的内部逻辑反驳同样有价值，不要求所有修正都等待外部工具。
5. 合并经核查且版本一致的局部成果；处理所有影响主结论的异议。重复同一论证或泛泛赞同没有增加证明状态。

作者与审查者尽量分离，但主 agent 可以修正数学内容。Scribe 和 Selector 是可选功能，由主 agent 承担也可以。证明前沿已经清楚时直接修最脆弱的引理，无需重跑一套仪式。

## 4. 验证看覆盖范围，不看工具层级

详细规则与常见误判见 [verification.md](references/verification.md)。每项证据都注明：**检验了哪个版本的什么结论、覆盖哪个域、依赖什么假设、有什么未覆盖项**。

- 有限抽样/浮点吻合/小 n 穷举支持探索；没有穷尽性与一般性论证，不能证明无限域命题。准确的合法反例可以否证全称命题；近似数值违例先确认误差及可行性。
- 符号计算只证明其实际适用域下的关系；完整有限域枚举须核查覆盖、实现和终止。候选自打印 `HARD_ACCEPT`、assert 全绿或旧账本的 accepted 均不构成自认证。
- 自然语言证明须逐步闭合关键引理、量词、隐含条件和文献应用。审查认可可交付 `proved-informally`，不得冒充 kernel 认证。
- Lean/Isabelle 等形式证明须核查完整目标、所有依赖和语义对应。片段编译不等于全定理；`sorry`/`admit`/未授权公理、不一致前提或篡改定义会破坏认证。编译失败、超时、缺库是该形式产物未通过，不是主命题为假。
- 工具与文本冲突时回到同一陈述、假设、版本和信任边界解决；不使用 `L0 > L1 > …` 一票覆盖。LLM 多数票、置信度和审美分数不是证明。

按**每个结果**登记状态：`open`、`candidate`、`experiment-supported`、`proved-informally`、`proved-formally`、`disproved`、`needs-review`。条件定理写为 “在 H 下，C”，再单列 H 的地位；未证 H 不得写成原题成立。任务是否交付完成另记，不以一个全局 accepted 布尔值代替这些事实。

## 5. 让反例改变知识，而不偷偷改变目标

先验证反例满足原定义；区分否证原命题、某个引理、某个方法、某个实现。方法失败不推出定理为假，未找到分离例不推出两个条件等价。

按障碍选择局部修补、换方法、分解、推广或收窄。没有固定 Rule 4 > Rule 5 > Rule 2 顺序。每次修订记录原文、新文、触发证据、关系（等价/加强/削弱/换域/不可比）、得失，以及下游复核范围。关系本身需要论证，未知就标未知。

理论发展特别检查：新公理是否买进原结论；标准例是否满足它；条件是否一致/非空；从新对象回到原对象的桥梁是否已证；有限近似到无限对象是否有紧性、相容性或一致控制。不能因有限影子模型通过就宣称无限理论闭合。

## 6. 收尾条件与人的理解

**数学结果已完成**：原目标（或用户明确接受的替代目标）得到覆盖完整的证明/反例；所有关键依赖闭合、异议处理完毕，版本一致。交付中显示其具体证明等级。

**阶段性交付**：有完整的部分/条件结果，仍有明确 gap；达到用户限制，或前沿经有区别的尝试后无可执行的新动作。保存复现材料、卡住的精确命题及下一步验收方式。搜索停滞叫停滞，未获证明叫未获证明；“一轮无反例”“命题没改”“守卫 PASS”均不能变成数学收敛。用户要求持续工作且存在有效新动作时继续；停止指令到来时保存现状并按其范围结束。

对拟交付结果做目标忠实性和内容检查：新增前提是否承担了整个结论；定义是否循环/空真；删掉实质条件后的错误强版本会在哪步失败。triviality/over-power/aboutness 可作诊断，不是机械验收；短证明、一次使用的新定义、不能给出两实例本身不是错误。

写清核心机制、困难步骤、假设使用位置、反例揭示的边界、与文献的关系和可复用引理。只在确有价值时增加推广，已知结果的漂亮重证也可符合用户目标；检索未命中不等于原创，不自授“顶刊”“重大突破”。

默认交付干净数学结果与必要过程记录，形式按用户要求和项目需要选择。完整研究可分别保存数学结果与过程；文件名或排版不能表示机器形式化等级。需要 LaTeX 时使用当前环境可用的编辑与编译工具，保留源码，如实报告编译问题。PDF 排版成功只表示文档构建成功。

研究依据与历史实践的适用边界见 [research.md](references/research.md)，仅在理解设计取舍或改进本技能时读。维护/验证本技能时读 [evaluation.md](references/evaluation.md)。
