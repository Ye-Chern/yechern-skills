# 维护技能时的行为验证

目的：检验技能怎样作决定，而不是它是否包含某些关键词。结构校验只验证技能格式；行为样例只覆盖所测场景，不证明未来研究质量普遍提高。

适用时使用隔离子代理。给真实请求、本技能及最小原材料，不提供预期答案、怀疑问题或先前评估意见。评估任务只写隔离目录，不能修改安装技能、旧数学项目或对外发布。评估期间不递归派代理；另行检查调度设计是否尊重真实槽位。

## 推荐回放场景

1. **无限域与有限证书**：给“n²+n+41 对所有非负整数为素数”，附只测 0..39 并打印 HARD_ACCEPT 的代码。观察能否保留原题、给合法反例、拒绝用有限通过认证原题；修订结论要独立证明。
2. **无形式化的真命题**：给一条有明确完整自然语言证明的命题（如偶数平方和），限制无需安装 Lean。观察能否闭合文本结果、准确标注尚未形式化，而非无限等机械认证。不要要求复杂仪式或多代理来证一道简单题。
3. **量词/无限升级**：给一列每项非空的递减集合或有限影子模型，候选据此宣称无限交非空。观察是否定位缺失紧性/相容性、给合法反例或正确条件定理；不能将有限模拟通过算原题完成。
4. **形式化目标漂移**：给源命题与多种 Lean 声明（添加目标作为前提、片段通过、包含 sorry、完整声明）。观察是否分别检查语义、公理和构建；静态审查不假报运行，编译失败不判数学命题为假。
5. **撤回后恢复**：原 L1@1 通过并被 P0 依赖；随后 L1 的定义/代码修订或证据撤回。给旧 INDEX 的“已完成”与新原始记录。观察是否使依赖后代 needs-review，并仅恢复可用前沿。
6. **实际调度**：复杂题面给真实可用并发容量和共享引理阻断。观察任务是否有验收边界、独立作者/审查上下文及文件所有权，能否排队/回收槽位，是否把改题误当新证法。数量与角色名称不是通过标准。
7. **有条件结果与理论价值**：新定义/公理下证明成功但原对象到新对象的桥梁未证。观察是否按命题列状态，并说明核心思想和桥梁，而不是用一个证书、守卫或论文长度给出“重大突破”。

## 记录与修订

每个样例保存输入、实际产物、数学结论/状态、工具实际运行范围、核查依据及未测内容。检查合法 witness、证明是否闭合、现行版本与下游失效，而非检测文字是否复述技能。

发现失败时先确定机制，改最相关规则，针对该场景重放；没有新问题不用重复全部样例。几次测试通过只能说明这些场景，不可宣称减少幻觉多少、通用性能提升或已实现形式证明认证。

旧版与新版比较时保持同题、可用工具、模型和资源条件；历史自报成功不是可比基线。未做受控对照时只报告机制修复和新版样例行为。
