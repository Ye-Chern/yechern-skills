# 命题演化、依赖失效与恢复

适用于跨阶段/跨会话、存在多分支或撤回的研究；不要每次工具调用都做记忆管理。

## 只保留一个现行入口

复用项目既有 START/BRIEF/README 作为入口。新任务可以采用：

```text
START.md             当前目标/状态/阻断/下一步及读取指针
CONTRACT.md          原题、允许修订的范围、验收、用户品味/限制
ledger.jsonl         主 agent 单写的关键事件（或已有等价账本）
claims.md            现行结论和依赖视图，可由账本更新
work/branches/<id>/  代理数学稿件/脚本/实际结果
sources/             有定位的最小来源记录
```

已有 durable-task 账本时用其节点和追加事件；不要再建另一套宣称同样权威的 ledger。上面是手工方案，不要求 SQLite。存数学稿件、关键理由和复现材料，不存私有思维链、全聊天或工具内部 transcript。

## 稳定 ID 与版本

推荐 `P0@1` 原题、`P1@1` 修订题、`L3@2` 引理、`D2@1` 定义、`E4@1` 证据、`CE2@1` 反例、`G1` 缺口。编号只是标识，不代表等级。更改同一数学对象给新 revision；另一个命题给新 ID 并记录关系。

一条核心记录至少包含：

```json
{
  "id": "L3",
  "revision": 2,
  "statement": "完整陈述，含全部假设与量词",
  "status": "proved-informally",
  "depends_on": ["D2@1", "L1@3"],
  "evidence": ["E4@1"],
  "proof_location": "work/branches/b1/lemma.md#L3",
  "validation": "实际核查方法与覆盖范围",
  "limits": "例如，尚未机器形式化"
}
```

此外，证据要有实际源文件/代码/输出位置、版本（可靠时用 hash/提交 ID）、目标与适用域。实现可用 Markdown 和 JSONL，不强迫所有返回都满足巨大 JSON 模式。

事件记录包含日期、对象/版本、发生了什么、具体依据和下游影响。登记关键失败分支：原先可行的具体理由、卡住的精确义务、否证/无结论的依据、怎样修复、什么新信息会使其值得重开。反例是可复用资产；未经验证的“动物园”案例保持候选。

## 撤回与传播

定义、陈述、假设、文献对应或证书代码改变：标记所有依赖后代 `needs-review`；证明依赖当时的版本，不能只看同一路径。把旧状态作为历史保留，不原地擦掉撤回原因。

例如 `D2@1 → L3@2 → P0@1`；D2 改为 @2 后，L3 与 P0 都须定向复核。新 D2 通过检查也不会自动复活旧 L3。证明能复用的部分可保留，但要重新确认适用性。

文件 hash 只能发现字节漂移，图只能传播已声明依赖，二者都不证明数学正确或依赖完备。没有脚本时手工检查相同边界。

修订的是研究目标时，失效的是旧结果在新目标下的应用，不必宣告固定旧陈述为假。例如紧致闭集定理在原范围内仍可成立；去掉紧致性的另一个命题应另给 ID。保留旧版本证明的地位，并将错误迁移到新范围的应用置为 needs-review；若旧证据本身撤回，则沿旧依赖也复核。不要混淆“历史有效”“当前可用”和“已被否证”。

## 阶段检查点

出现命题修订、反例、撤回、关键引理闭合、用户约束变化、阶段交付或分支切换时保存。START 保持足够短，给：

- 正在解决的原目标与用户最新约束。
- 当前可用结果及其版本/状态；已撤回且不能引用的结果。
- 最实质的未解义务与失败路线指针。
- 现在运行/已结束的代理任务及其结果目录；未知状态不能假定仍在运行。
- 一项下一动作、输入和可验收输出。

任务结束与定理状态分开。例如“此次交付完成：给出了 P0 的反例和 P1 的条件结果；G2 仍 open”。不要因已写完报告就把所有 open 项标 done。

## 恢复

先读现行入口和契约，再定向读前沿依赖。使用 durable-task 脚本时先 resume 校验；手工模式确认文件/版本、撤回和后代。聊天摘要和 INDEX 是路由线索，不能代替现行原始依据。

旧 `HARD_ACCEPT`/`accepted=true`、旧成功日志或“顶刊水准”只记“历史记录声称”。为本次要使用的确切结论核查其证明和证据范围，不重跑全部历史任务。工具链变更、被撤回依赖或代码漂移时按影响范围复核。

跨任务发现只作为线索：保留来源任务和精确陈述，把它应用到本题时重新匹配定义与假设。不因关键词相同唤醒大批任务，也不未经用户授权发外部消息或自动重开休眠研究。
