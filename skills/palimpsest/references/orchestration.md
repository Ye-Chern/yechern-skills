# 按数学障碍分工

这里是任务接口，不是必须全部启动的人物表。不预设模型比负责人弱；不同名字、不同温度或不同模型都不能自动消除相关错误。默认继承当前模型/推理设置，只有用户或适用指令要求时才改。

## 什么时候值得派代理

一个代理应能交付独立可验收的义务：某个引理、不同证法、具体反例、来源定理匹配、有限构造、形式化模块、或完整候选的审查。若必须实时共享几乎全部上下文且没有清楚任务边界，主 agent 先做分解。不要把一段连续证明为了角色齐全切碎。

建议按问题选功能：

- **路线探索**：在同一目标下提出实质不同机制、关键引理及最快能区分可行性的检查。只交几个有内容的路线，不以 2–7 个轴为配额。
- **证明**：闭合指定目标；标出确切新假设、引用和未证义务。不能为了让证明成立擅改题面。
- **反例**：攻击原题或具体薄弱点，给完整 witness 和每项假设核查。与证明并行时从原题独立找；候选出现后可以定向攻击。
- **文献**：找精确可调用定理/反例，返回原文位置与假设对应；不只返回标题和搜索摘要。
- **审查**：重建关键推论，尤其是最薄弱或最有原创性的步骤；指出最早未闭合义务，给具体计算或反例。认可必须说明覆盖范围。
- **形式化**：把固定陈述与依赖变成完整可检查产物；库缺口可通过新引理解决，数学内容改变必须回报。
- **成文**：只从现行已核查结果生成可读证明，不能把 gap 润色成“显然”。复杂局部可用 Lamport 的层次结构，不规定深度/节点数。

主 agent 持有目标、主稿和当前状态。少量开放分支即可；一个任务返回后可复用该 agent 做有明确新输入的后续任务，避免无谓重建。独立审查一般另开隔离上下文，不复用作者作为自己的唯一审查者。

## 可直接改填的派活包

```text
任务：证明/攻击/检索/审查 <精确义务>。
对象：P0@2；定义 D1@1；允许前提 H1@1、L2@3。
目的：此结果将解除 <哪个依赖/区分哪些路线>。
输入：<相关原文/来源/文件的绝对路径与定位>。
边界：保留目标的域、量词和结论；需要改动时作为候选修订另列。
方法约束（只在必要时写）：<指定表征/禁止循环引用/证书范围>。
交付：精确陈述；完整证明或合法反例；依赖与未解义务；
      检验方法、实际原始结果/来源定位、适用范围；与原目标的差别。
停止：义务闭合/发现首个有效致命反例/明确不能闭合及障碍；
      不用不受控重试代替交付。不虚报未执行的检查。
目录：<任务根的绝对路径>/work/branches/<branch-id>/。
只写该分支；输入只读。主稿/账本由负责人合并。
返回文件索引和关键结果摘要；数学证明写进可审查产物，
不提交隐藏思维链或全聊天 transcript。
```

依赖输入不在同一条消息时给精确文件指针；不要复制所有历史。声明是只看数学内容的独立审查时，不提供领导意见、其他审查者评分、预期答案或作者身份；必要的已知定理/假设不能为了“盲”而删掉。

## 调度与返回

用当前原生工具的语义，不照抄旧 Qoder 的 Agent 参数。在提供 collaboration 的环境中：`spawn_agent` 派活，`send_message` 对运行中的代理追加精确反馈，`followup_task` 接续一个已结束任务；`wait_agent`/结果通知用于等待。只按当前工具文档使用这些接口；没有时采用可用的等价接口。

并发先确认可用容量，主 agent 占一个槽。任务排队而不是按难度开 20 个代理；不创建旁边可见的独立用户聊天来代替内部子代理。父 agent 做不可被代理替代的整合、证据检查、关键数学和持久化工作。

等待时处理独立事项或用事件等待；避免频繁轮询，按当前交互规范给简短进展。不读工具私有的全量 transcript；可以定向读代理主动交付的数学稿件、代码和原始结果。慢/空返回是运行问题，不是数学失败；按实际错误修复一次或调整任务，重复同一故障时转本地工作或交付明确限制，不无穷重启。

先接受局部结果，再合并：输入版本匹配？新定义与主稿一致？是否偷偷增加假设？输出证据是否真的覆盖所声称义务？与其他分支是否矛盾？通过这些问题后才能修改主状态。汇总“两个 agent 都说对”没有完成此步骤。

## 怎样让再尝试产生信息

允许内部逻辑审查及具体自我修正。禁止的是空泛重试的验收升级，不是数学家正常地重新思考。

有效反馈例： “L3 第 4 步把有限条射线的并当有限点集，给出修复或合法反例”；“用序理想表征尝试同一 P0，沿上一阻断的不同侧推进”；“工具结果与公式不符，先核查符号约定”。

若意见冲突，围绕最小分歧命题安排重建/计算/查源；可以交流可定位的证明、反驳和来源。不要禁止所有互评，也不要让反复对话、赞同或评分成为结论依据。

默认不允许子代理再递归派代理；只有负责人能说明任务进一步分拆的收益并协调剩余槽位时才授权，仍服从当前运行约束。
